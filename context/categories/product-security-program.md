# Product security program

The operating system of product security: design review, secure engineering expectations, and who signs off before a feature ships. Tools support it. The program is not a SKU.

**Buyer question:** How does a feature get a security review, and what happens when the answer is no?

**Usual owner:** Head of product security.

**Budget source:** Engineering leadership. Tooling is a slice of it.

## Owning seats

- Product security lead (`product-security`)

## What buyers do instead

- AppSec team covers product security part-time. Good enough when: One product line and few customer security demands. Breaks when: Customer reviews, disclosure, and secure design work outgrow the AppSec queue. — hypothesis
- Engineering owns security informally. Good enough when: Early stage with no enterprise customers yet. Breaks when: An enterprise deal, incident, or regulator needs a named owner and a program. — hypothesis
