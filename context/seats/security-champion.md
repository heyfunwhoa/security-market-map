# Security champion

Local security contact inside a product engineering team; translates AppSec asks into team work.

## Typical titles

- ic: Security Champion
- senior-ic: Senior Security Champion

## Owns categories

- Static analysis (SAST) (`sast`)
- Software composition analysis (`sca`)
- Secrets detection and remediation (`secrets-detection`)
- Threat modeling (`threat-modeling`)

## Pains

- Developers lose hours a week triaging noisy security findings — sourced ([Digitalisation World](https://m.digitalisationworld.com/news/68715/growing-developer-focus-on-software-security))
- Security work isn't in the sprint plan — hypothesis
- No time or training to triage findings — hypothesis

## Objections

- "We don't have sprint time for security work." Usually about: Security work isn't prioritized or estimated like product work. Reframe to test: Size the work in sprint terms, route only high-confidence findings, and ask whether it can enter the backlog like any other bug. — hypothesis

## Qualification questions

- Is there a champions program with some time set aside? Good fit if: Named champions per team and a regular sync. (medium weight, hypothesis)
- Do champions triage findings for their team? Good fit if: Champions own the first pass on alerts. (medium weight, hypothesis)
- Is the champion role informal with no time allotted? Poor fit if: Champions are volunteers with no hours. (low weight, hypothesis)
