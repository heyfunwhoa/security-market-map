# External attack surface management and cyber threat intelligence

The exposure management team asks which internet-facing assets belong to the organization and who can fix them. The intelligence team asks which threats warrant a decision, what evidence supports that assessment and who needs the result. A sector advisory can connect the two when an exposure owner identifies the affected asset.

#### Find exposed assets and dependencies

| Buyer scenario | What connects it to the company? | Example options and original evidence |
| --- | --- | --- |
| **External attack surface management**. After an acquisition, a customer finds an old support portal missing from the asset inventory. Is it still theirs? | Use the domain history, subsidiary relationship and current service owner to confirm the portal belongs in the inventory. Exposure management identifies the asset. Infrastructure confirms ownership and resolves the finding. | [Microsoft Defender EASM](https://learn.microsoft.com/en-us/azure/external-attack-surface-management/overview) Defender EASM uses external infrastructure relationships to discover an organization’s internet-facing assets and build an inventory.<br>[CyCognito](https://www.cycognito.com/documents/datasheets/DS-CyCognito_Discovery_and_Contextualization_2023Q2_v1.pdf) CyCognito describes mapping externally visible assets to the companies and subsidiaries associated with them.<br>[Cortex Xpanse Expander](https://docs-cortex.paloaltonetworks.com/r/Cortex-XPANSE/2/Cortex-Xpanse-Expander-User-Guide/Asset-Attribution) Expander shows whether Xpanse discovered an asset or the customer supplied it, and which observed data matched the starting identifier. |
| **Public API discovery**. The mobile app still works after the old customer portal is retired. Which API host or endpoints support it? | Match the host or observed route to a gateway, application and team. Ask which endpoints would be invisible without traffic. The API platform owner and application team decide whether to keep, protect or retire it. | [Wallarm API Attack Surface Management](https://docs.wallarm.com/api-attack-surface/overview/) Wallarm describes agentless discovery of public API hosts within the external scope configured for its API Attack Surface Management service.<br>[Cloudflare API Shield API Discovery](https://developers.cloudflare.com/api-shield/security/api-discovery/) Cloudflare discovers API endpoints from traffic on its network using machine learning or configured session identifiers.<br>[Salt Connect](https://salt.security/connect) Salt Connect builds an API inventory from cloud and code configuration through read-only connectors for AWS, Azure, Google Cloud and GitHub. |
| **DNS and certificate monitoring**. A campaign ends. Its old subdomain still points to a retired service, and a certificate appears for a similar hostname. Who owns each? | Check the exact hostname, certificate name and service record against what the DNS and certificate owners intended. DNS operations reviews stale records. The PKI team investigates unexpected issuance. | [DigiCert Trust Lifecycle Manager](https://docs.digicert.com/en/trust-lifecycle-manager/build-your-inventory-and-ecosystem/discovery-tools/ct-logs-monitoring.html) DigiCert Trust Lifecycle Manager monitors public Certificate Transparency logs for certificates matching configured organizations or base domains.<br>[Detectify Surface Monitoring](https://support.detectify.com/support/solutions/articles/48001145084-subdomain-takeover) Detectify describes reporting an in-scope subdomain whose DNS record still references a disconnected service.<br>[SSLMate Cert Spotter](https://sslmate.com/certspotter/) Cert Spotter monitors certificates issued for a customer’s domains. The customer can specify expected certificates or trusted authorities to narrow alerts. |
| **Third-party attack surface monitoring and ratings**. A payroll provider’s security rating drops. Which finding warrants a conversation with the supplier? | Ask the supplier to confirm the asset and observation. Map the affected service to the contract and business process. Third-party risk contacts the supplier’s security owner and tracks the response. | [Bitsight Continuous Monitoring](https://www.bitsight.com/products/continuous-monitoring) Bitsight describes monitoring a portfolio of third parties for changes in security posture so teams can prioritize vendor follow-up.<br>[SecurityScorecard Ratings](https://securityscorecard.com/wp-content/uploads/2026/04/MethodologyDeepDive-3.0-Ebook_051926_SD.pdf) SecurityScorecard describes attributing externally collected signals to company assets and using those signals to calculate security ratings.<br>[UpGuard Vendor Risk](https://help.upguard.com/en/articles/3764556-what-is-upguard-vendor-risk) UpGuard lets teams group monitored vendors and track remediation requests against an individual supplier’s risk profile. |
| **Package impersonation and dependency risk**. A proposed dependency differs from a familiar package name by one letter. Could it enter the company’s build? | Match the exact package, version and request to the repository or build. Registry-wide monitoring of a company’s brand is a separate capability to verify. Developer security and the build owner review the dependency or block the request. | [Socket dependency alerts](https://docs.socket.dev/docs/what-to-do-with-socket-alerts) Socket documents an alert for a dependency whose name resembles another package and directs the reviewer to check whether that dependency was intended.<br>[Sonatype Firewall Pro](https://help.sonatype.com/en/firewall-pro-blocking-logic.html) Sonatype documents evaluating package requests in Firewall Pro and blocking potentially malicious components, including suspected typosquats.<br>[JFrog Curation](https://docs.jfrog.com/security/docs/list-of-available-conditions) JFrog Curation offers a policy condition that blocks third-party packages its security research team has identified as malicious. |

#### Find leaked company material

| Buyer scenario | What connects it to the company? | Example options and original evidence |
| --- | --- | --- |
| **Public secrets monitoring**. An employee accidentally publishes a company API key from a personal account. Who can identify the key and revoke it? | Separate the identity of the person who posted it from ownership of the key. Check the vendor’s attribution evidence and verification for that credential type. AppSec identifies the credential owner, who revokes or rotates the key and checks usage. | [GitGuardian Public Monitoring](https://docs.gitguardian.com/public-monitoring/sources/overview) GitGuardian monitors new and historical public GitHub commits. Its historical scans also cover public Gists and, for selected workspaces, public Docker Hub image layers. · [Company public perimeter](https://docs.gitguardian.com/public-monitoring/perimeter/overview)<br>[GitHub Secret Protection public monitoring](https://docs.github.com/en/enterprise-cloud@latest/code-security/concepts/secret-security/public-monitoring) GitHub looks across public GitHub repositories, Gists, and issue and pull request comments. Enterprise membership or a verified email domain connects a finding to the enterprise. With data residency, attribution uses verified domains. · [Public monitoring for enterprises generally available](https://github.blog/changelog/2026-10-28-public-monitoring-for-enterprises-generally-available/)<br>[Truffle Security Forager](https://trufflesecurity.com/docs/user-enablement-guide) Forager monitors public GitHub commits and npm package releases for exposed secrets. Its company view presents verified keys associated with an email domain. · [Introducing Forager](https://trufflesecurity.com/blog/introducing-forager)<br>[CybelAngel public repository case](https://cybelangel.com/blog/alert-of-the-month-code-repository-gone-bad/) CybelAngel reports finding CRM access tokens in a developer’s personal public repository. This is a vendor-described customer case. |
| **Public code and configuration leaks**. A personal repository contains a file resembling an internal deployment template. Is this actually company code? | Compare the material with a known internal file and ask its maintainer to confirm the match. Check separately for embedded credentials. The CTI analyst and engineering owner verify the leak and coordinate removal. AppSec handles any exposed secrets. | [Flare Cyber Threat Intelligence Platform](https://docs.flare.io/queries) Flare documents investigating potential code or configuration leaks on public GitHub using organization-specific project names or code fragments.<br>[Recorded Future Brand Intelligence](https://assets.recordedfuture.com/Datasheets/brand-intelligence-module.pdf) Recorded Future describes monitoring code repositories, paste sites and dark web forums for exposed company data, including proprietary code and employee credentials.<br>[SOCRadar Brand Protection](https://socradar.io/blog/implementing-cyber-threat-intelligence-in-software-development-lifecycle-sdlc-pipelines/) SOCRadar describes monitoring public GitHub and GitLab repositories for exposed code, login credentials and API keys and alerting organizations to potential leaks.<br>[Outpost24 Data Leakage](https://outpost24.com/wp-content/uploads/2026/03/Service-Specific-Terms-EASM-with-Threat-Intelligence.pdf) Outpost24’s Data Leakage module searches external sources including public and cloud document repositories for exposed documents and confidential material. The module also searches public repositories for source code. |
| **Public cloud storage exposure**. A customer export sits in cloud storage. Can anyone read it, and who can change the permission? | Confirm the bucket or container, account owner, intended audience and effective access. Access logs are separate evidence of a download. Cloud security and the data owner adjust permissions and verify the resulting access. | [AWS IAM Access Analyzer for S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-analyzer.html) AWS identifies S3 general purpose buckets with public or cross-account access and shows the source and level of the permission. The console uses a regional external access analyzer.<br>[Microsoft Defender CSPM](https://learn.microsoft.com/en-us/azure/defender-for-cloud/concept-data-security-posture-prepare) Microsoft documents separate conditions for network exposure and public access in Defender CSPM storage insights, including anonymous-read settings for Azure Blob containers.<br>[Google Security Command Center Enterprise](https://docs.cloud.google.com/security-command-center/docs/playbooks-public-bucket-acl) Security Health Analytics identifies publicly accessible Cloud Storage buckets. Security Command Center Enterprise can route those findings to a remediation playbook. |
| **Exposed documents and sharing links**. A supplier may have posted an internal price list. Is there an external copy, or did someone create a broadly accessible link inside the company? | Have the document owner confirm the file and intended recipients. Identify which organization controls the copy or link. The data owner works with supplier management on an external copy or a tenant admin on an internal sharing link. | [Outpost24 Data Leakage](https://outpost24.com/wp-content/uploads/2026/03/Service-Specific-Terms-EASM-with-Threat-Intelligence.pdf) Outpost24’s Data Leakage module searches external sources including public and cloud document repositories for exposed documents and confidential material. The module also searches public repositories for source code.<br>[SharePoint Advanced Management](https://learn.microsoft.com/en-us/sharepoint/data-access-governance-sharing-links-report) SharePoint Advanced Management identifies tenant sites with the most new sharing links in the last 28 days, including links that allow access without signing in.<br>[CybelAngel Data Breach Prevention](https://cybelangel.com/data-breach-prevention/) CybelAngel describes analyst reports that include the origin of a leak and samples of exposed documents for the customer to review. |

### Public monitoring buyer conversation

Ask what the customer wants to find. An unknown internet-facing host belongs with the exposure team. A company API key in a personal repository needs an attributed alert and an owner who can revoke the key. Copied proprietary code may need a takedown. An employee login in a breach report belongs with identity response. A single incident can involve several of these teams.

| Buyer decision | Offerings to evaluate | Evidence to ask for |
| --- | --- | --- |
| Find an organization-linked secret in public developer activity | GitGuardian Public Monitoring, GitHub Secret Protection public monitoring, Truffle Security Forager | The actual source covered, historical or ongoing detection, the attribution signal, and who can act on the alert. |
| Investigate reports of exposed code or company data | Flare public repository leak investigation, Recorded Future Brand Intelligence, SOCRadar Brand Protection, CybelAngel Data Breach Prevention, Outpost24 Data Leakage | A reviewed code or data match, the analyst handoff, and how the team tracks removal and credential rotation. |
