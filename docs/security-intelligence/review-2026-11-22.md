# Review record: secret type and exposure location (2026-11-22)

**Reviewer:** Kristen Aing. **Drafted by:** agent. **Scope:** two new reviewed fields for all 46 published incidents, plus an Okta source update.

## Fields

Stored in `data/security-intelligence/incident-secret-exposures.json`, one entry per incident, following the same reviewed-file pattern as industries.

- **Secret type:** the kinds of secret the sources say were exposed or stolen. Values: cloud access key, Git platform token, CI/CD secret, AI provider key, API key (non-AI, internal or third-party), OAuth or integration token, session or SSO token, service account or machine credential, password, package registry token, SSH key, database credential, signing or encryption key, many types.
- **Where it was exposed:** where the _first_ exposed secret sat, not every store the attacker reached afterwards. Values: public code repo, private code repo, CI/CD pipeline or logs, build artifact or image, developer machine, exposed app config, vendor or platform, support/chat/work files, personal account or browser profile.

Rules applied: a value only where a source states it; otherwise the field stays empty ("Not stated"). "Many types" is distinct from not stated: it means the source reports a whole set of secrets, such as a platform's environment variables, without breaking it down. An incident can have more than one value.

Review changes from the first draft: split code repo into public and private; added SSH key, non-AI API key and database credential; renamed signing key to signing or encryption key; separated "many types" from unknown; added "personal account or browser profile" for Okta.
